# BOSQ 3D Product Viewer — Implementation Plan

**Prepared:** 15 September 2026
**Project:** `bosq-3d-products` (standalone Next.js app, deployed on Vercel)
**Audience:** BOSQ stakeholders and the engineering team that will build it

---

## 1. What we found on bosq.ae

| Finding | Why it matters for this project |
|---|---|
| bosq.ae is a **Next.js** site with a custom backend at `backend.bosq.ae` (no Shopify / WooCommerce / Magento) | The viewer can be built in the same stack, embedded via iframe in Phase 1, and later imported as a shared React package into the main site. No plugin-ecosystem constraints. |
| Product URLs: `/en/products/[slug]?sku=[SKU]&attr_color=[color]` (e.g. `monarch?sku=MON-HB-DARK-BLUE&attr_color=dark-blue`) | `slug + sku + colour` is already the product identity. The 3D catalogue keys on exactly the same triple, so a "View in 3D" link can be generated with no new data on the main site. |
| Product page: 5-image thumbnail carousel, price, Add to Cart / Buy Now / Enquire Now, Technical Data Sheet PDF, specs (W70 × D78 × H119–129 cm) | The 3D viewer belongs as the **first tile in the gallery** (or a button beneath it). Real dimensions are available for a "show dimensions" overlay. |
| Design language: white header with the orange BOSQ logo, accent `#F17423`, ink `#282828`, light surfaces `#F9F9F9`/`#F4F4F4`, "Hero New" typeface (Cairo for Arabic), small uppercase light-weight buttons | The viewer's chrome, loading state and lighting must match — premium, neutral, no visual noise around the product. Tokens are sampled from bosq.ae's CSS. |
| Locales: `/en/` prefix (Arabic is expected for a UAE brand) | Build the viewer app locale-aware (`/[locale]/…`) from day one; RTL-safe UI. |
| Payments via Tabby; enterprise clients (BMW, Audi, Siemens) | The audience is B2B buyers inspecting build quality. Material fidelity (Napa leather, chrome, mesh) matters more than gimmicks. |
| No 3D/AR features exist today | Greenfield — no migration. |

## 2. Recommended solution in one paragraph

Build a standalone **Next.js 16 + React Three Fiber** application at `3d.bosq.ae`, hosted on Vercel, that renders optimised **GLB** models (converted from your OBJ files through an automated pipeline) with a premium studio-lighting setup, orbit/zoom/pan controls, a dimension overlay and native mobile AR. Models are served from a zero-egress object store (Cloudflare R2) behind a CDN. bosq.ae product pages get a **"View in 3D"** button that opens the viewer in a lightweight iframe/modal (Phase 2) and later as a first-party component. The product catalogue is a JSON manifest in Phase 1 and moves to `backend.bosq.ae` once the pipeline is proven — which is what makes scaling to hundreds of products a data problem rather than a code problem.

## 3. Technology stack

| Layer | Choice | Rationale |
|---|---|---|
| Framework | **Next.js 16 (App Router), React 19, TypeScript** | Same stack as bosq.ae; SSR for the SEO-facing shell; first-class Vercel deploys. |
| 3D engine | **three.js** (latest r17x) | Industry standard; largest ecosystem for glTF, KTX2, Draco, Meshopt. |
| React binding | **@react-three/fiber v9** + **@react-three/drei** | Declarative scenes, Suspense-based loading; drei provides `Stage`, `Environment`, `ContactShadows`, `Html` (hotspots), `Bounds`, `PerformanceMonitor`, `useGLTF`, `Preload`. v9 is the line paired with React 19 — v8 does not work with Next 15+. |
| Post-processing (optional) | @react-three/postprocessing | SSAO / bloom on desktop tier only. |
| State | **zustand** | Tiny; shares camera/variant state between viewer and UI. |
| Styling | **Tailwind CSS v4** | Fast; easy to mirror bosq.ae tokens. |
| Model pipeline | **obj2gltf**, **@gltf-transform/cli**, **KTX-Software (toktx)**, **Blender** (manual clean-up when needed) | The de-facto glTF toolchain. Scriptable, CI-friendly. |
| Posters / thumbnails | **playwright-core** (drives the installed Edge/Chrome — no browser download) + **sharp** | Generates `poster.webp` + OG image per product automatically. |
| iOS AR | **USDZ** generated by three.js `USDZExporter` at build time | Apple AR Quick Look needs USDZ; Android Scene Viewer uses the GLB directly. |
| Model storage | **Cloudflare R2** (custom domain `models.bosq.ae`) | Zero egress fees; Vercel bandwidth is metered and hundreds of 2–4 MB models × traffic adds up. Alternative: Vercel Blob for simplicity in Phase 1. |
| Hosting | **Vercel** (Pro) | Preview deployments per PR, edge caching, Analytics, Speed Insights. |
| Catalogue | JSON manifest in repo (Phase 1) → `backend.bosq.ae` REST endpoint (Phase 3) | Start simple; no backend change needed to launch. |
| Analytics | Vercel Analytics + custom events (`3d_open`, `3d_rotate`, `ar_launch`, `variant_switch`) | Measure conversion impact. |
| Tooling | npm, ESLint, Vitest, Playwright (visual regression of viewer) | |

**Why React Three Fiber instead of `<model-viewer>`?** Google's `<model-viewer>` web component is the fastest way to get a rotating GLB on screen (and it remains a valid fallback). But every item on the "future enhancements" list — configurators, material switching, hotspots, room placement, custom lighting per product — needs scene-level control that `<model-viewer>` does not expose. R3F gives that control while keeping the code declarative and maintainable.

  "variants": [
    { "sku": "MON-HB-DARK-BLUE", "color": "dark-blue", "label": "Dark Blue",

    { "sku": "MON-HB-BURGUNDY", "color": "burgundy", "label": "Burgundy",

Variants map to **named materials** inside the GLB (`Leather`, `Mesh`, `Base`). That single convention is what unlocks colour switching and configurators later without re-exporting models.

### 4.4 Embedding on bosq.ae (Phase 2 integration)

```tsx
// bosq.ae — product page, next to the gallery
<button onClick={() => setOpen(true)}>View in 3D</button>

{open && (
  <Modal>
    <iframe
      src={`https://3d.bosq.ae/embed/${slug}?sku=${sku}&lang=${locale}`}
      allow="xr-spatial-tracking; fullscreen"
      loading="lazy"
      title="3D viewer"
    />
  </Modal>
)}
```

The embed posts `{ type: "bosq3d:ready" }`, `{ type: "bosq3d:variant", sku }`, `{ type: "bosq3d:ar" }` to the parent, and accepts `{ type: "bosq3d:setVariant", sku }` — so choosing a colour on the product page updates the model and vice versa. Phase 4 replaces the iframe with a direct import of `@bosq/viewer` (this repo published as a package), eliminating the iframe boundary.

## 5. Model optimisation workflow (OBJ → GLB)

OBJ files are unsuitable for the web as-is: no PBR materials, no compression, textures often 4K PNGs, and typically 5–50× larger than an optimised GLB. Every product runs through this pipeline once; outputs are versioned (`/v3/`) and cached forever.

### 5.1 Steps

| # | Step | Tool | Notes |
|---|---|---|---|
| 1 | **Intake** | — | Drop `models-src/<slug>/` with `.obj`, `.mtl`, textures. Record real dimensions and SKUs. |
| 2 | **Clean-up (manual, once per product)** | Blender | Apply scale so 1 unit = 1 metre; centre at origin, floor at y = 0; merge duplicate verts; fix flipped normals; name materials (`Leather`, `Mesh`, `Base`, `Plastic`); assign PBR values (roughness/metalness); bake AO if there is no AO map. Most of the "premium" look comes from this step. Export GLB. |
| 3 | **Automated conversion (if skipping Blender)** | `obj2gltf` | `npx obj2gltf -i in.obj -o raw.glb --metallicRoughness` |
| 4 | **Optimise** | `@gltf-transform/cli` | `gltf-transform optimize raw.glb out.glb --compress meshopt --texture-compress ktx2 --texture-size 2048 --simplify --simplify-error 0.001 --join --flatten --prune` |
| 5 | **Mobile LOD** | `gltf-transform` | Same, with `--simplify-ratio 0.35 --texture-size 1024` → `*.lod1.glb` |
| 6 | **USDZ** | three.js `USDZExporter` (node) | For iOS Quick Look. Uncompressed textures, ≤ 25 MB. |
| 7 | **Poster / OG** | playwright-core + sharp | Renders the exact hero camera; `poster.webp` 1200×1200 + `og.png` 1200×630. |
| 8 | **Validate** | `gltf-validator`, budget check | Fails the pipeline if the size or triangle budget is exceeded. |
| 9 | **Manifest** | script | Computes bounds, stats; merges hand-written `variants` / `hotspots`. |
| 10 | **Upload** | R2 SDK | `models.bosq.ae/<slug>/v<n>/…` with `Cache-Control: public, max-age=31536000, immutable`. |

`npm run pipeline -- monarch` runs steps 3–5 and 8–10; `npm run poster -- monarch` runs step 7. Step 2 is the only human-in-the-loop step; budget 1–3 hours per product for a 3D generalist, less as the source files get cleaner.

### 5.2 Budgets (enforced by the pipeline)

| Asset | Desktop (high) | Mobile (low) |
|---|---|---|
| GLB size (compressed) | ≤ 3 MB (target 1.5–2.5) | ≤ 1 MB |
| Triangles | ≤ 150 k | ≤ 50 k |
| Texture resolution | 2048² KTX2 (UASTC for leather/normal maps, ETC1S for the rest) | 1024² ETC1S |
| Draw calls / materials | ≤ 12 | ≤ 8 |
| Time to first 3D frame (4G) | < 2.5 s | < 3 s |

Why **meshopt + KTX2** rather than Draco + PNG: KTX2 textures stay compressed on the GPU (5–8× less VRAM — the main cause of mobile crashes), and meshopt decodes faster than Draco with a tiny WASM decoder. Draco remains a fallback option in the script.

## 6. Hosting & deployment on Vercel

1. **Repo:** GitHub `bosq/bosq-3d-products`; `main` = production; PRs get Preview URLs automatically.
2. **Vercel project:** Framework Next.js, Node 22; Serverless region `fra1` or `bom1` (closest to Dubai — choose by Speed Insights). Static routes are edge-cached globally regardless.
3. **Domains:** `3d.bosq.ae` → Vercel; `models.bosq.ae` → Cloudflare R2 custom domain.
4. **Env vars:** `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `MODELS_BASE_URL`, `BOSQ_API_URL` (Phase 3), `NEXT_PUBLIC_SITE_URL`.
5. **Headers (next.config.ts):** `Content-Security-Policy: frame-ancestors https://bosq.ae https://*.bosq.ae` on `/embed/*` so only BOSQ can embed it; `X-Robots-Tag: noindex` on `/embed/*`. No COOP/COEP needed (no SharedArrayBuffer).
6. **Caching:** `/api/products/[slug]` → `s-maxage=300, stale-while-revalidate=86400`; product pages ISR `revalidate = 3600`; decoders in `/public` immutable.
7. **Asset pipeline in CI (optional):** GitHub Action triggered on `models-src/**` push; runs `npm run pipeline`, uploads to R2, opens a PR updating `data/catalog.json`. Keeps large binaries out of git (source OBJs live in R2 too, or in a shared drive).
8. **Monitoring:** Vercel Analytics + Speed Insights; Sentry for WebGL context-loss errors; a custom `webgl_unsupported` event.
9. **Rollback:** Vercel instant rollback for the app; models are versioned so a bad `v4` never overwrites `v3`.

## 7. Performance optimisation recommendations

**Loading**
- Show `poster.webp` instantly (SSR'd `<img>`), then hydrate the `<Canvas>` (`dynamic(..., { ssr: false })`) and cross-fade when the model is ready. Users see the product in < 500 ms even if the GLB takes 2 s.
- Pick `model.low` or `model.high` by device tier (`navigator.deviceMemory`, `hardwareConcurrency`, `connection.effectiveType`, WebGL renderer string) before requesting anything.
- Preload the GLB on hover/pointerdown of the "View in 3D" button (`<link rel="preload" as="fetch">`, triggered via postMessage from the parent page).
- Self-host Draco/Basis decoders under `/public/decoders` and initialise them once (singleton in `loaders.ts`).
- HTTP/2 + immutable caching means a returning visitor's second product loads only the new GLB (~2 MB).

**Rendering**
- `frameloop="demand"` — render only when the camera or state changes; an idle chair costs 0 % CPU/battery.
- Clamp DPR: `dpr={[1, 1.75]}` desktop, `[1, 1.5]` mobile; drei `<AdaptiveDpr>` + `<PerformanceMonitor>` drop shadows/DPR when FPS < 45.
- One compact HDRI (`studio_small_1k.hdr`, ~300 KB) for reflections; `ACESFilmic` tone mapping; `ContactShadows` (cheap, rendered once) instead of real-time shadow maps on mobile.
- Baked AO in textures rather than SSAO on mobile; SSAO only on desktop tier.
- `<Bvh>` for fast raycasting once hotspots arrive; `<Bounds fit>` auto-frames any product regardless of scale.

**Memory / stability**
- Dispose geometries/textures/materials on unmount and on variant change (`useGLTF.clear`).
- One `<Canvas>` per page — never multiple WebGL contexts (iOS caps at ~8 and they die silently).
- Handle `webglcontextlost` → show poster + "Reload 3D view".
- Cap texture count/size in the pipeline (the single biggest mobile crash cause).

**Bundle**
- three.js tree-shaken via ESM; viewer chunk ~350 KB gz — loaded only when the viewer mounts.
- Keep the embed route free of the main site's UI framework weight.

**Targets:** Lighthouse mobile ≥ 90 on the full product page; WebGL first frame < 2.5 s on a mid-range Android over 4G; no memory growth after 10 variant switches.

## 8. SEO considerations

3D canvases are invisible to crawlers, so SEO is about everything *around* the canvas:

- **Canonical to bosq.ae.** `3d.bosq.ae/en/products/monarch` sets `<link rel="canonical" href="https://bosq.ae/en/products/monarch">` so the viewer never competes with the real product page. `/embed/*` is `noindex, nofollow`.
- **Server-rendered shell:** product name, description, dimensions and materials in HTML (from the manifest), not injected client-side.
- **Structured data:** `Product` JSON-LD with `offers` (AED price from bosq.ae), `image` (poster), and a `3DModel` object (`schema.org/3DModel`, `encodingFormat: "model/gltf-binary"`).
- **Open Graph / Twitter cards:** the auto-generated `og.png` (product on studio backdrop) makes shared links look premium on WhatsApp/LinkedIn — where B2B deals actually get shared.
- **`hreflang` en/ar**, locale-prefixed URLs, translated `alt`/`title`.
- **Sitemap** (`app/sitemap.ts`) listing full-page viewer URLs only; robots.txt blocking `/embed/` and `/api/`.
- **Performance is SEO:** the poster-first strategy keeps LCP on the image, not the canvas; CLS = 0 by reserving the viewer's aspect-ratio box.
- **On bosq.ae itself:** add the viewer link as a real `<a href>` (not only JS) and mention "3D view" in product copy.

| OBJ sources vary wildly in quality (CAD exports with millions of triangles, no UVs) | Phase 0 audit on 3 files sets realistic per-product artist time; pipeline decimation handles moderate cases, heavy CAD needs retopology. |
| Textures/materials in OBJ/MTL are not PBR | Blender pass assigns PBR values; build a small BOSQ material library (leathers, meshes, chromes, laminates) reused across products. |
| Mobile memory crashes | KTX2 + LOD + budget enforcement; tested on low-end Android in Phase 1. |
| Vercel bandwidth cost at scale | Models on R2 (free egress); Vercel only serves HTML/JS. |
| bosq.ae changes needed from their team | Phase 1 needs zero changes; Phase 2 needs one button + iframe (~1 day). |
| Who owns the model files long-term? | R2 bucket under BOSQ's Cloudflare account; source OBJs archived alongside. |
